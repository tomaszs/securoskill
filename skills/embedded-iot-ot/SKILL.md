# Embedded, IoT, and operational technology

## When to use

Load this skill when work touches **embedded, iot, and operational technology**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Firmware update security**: Signed images, Rollback protection, OTA channels, …
- **Secure boot and trust anchor**: TPM, eFuse, Chain of trust, …
- **Device communications**: MQTT TLS, CoAP, BLE pairing, …
- **Default credentials**: UART shells, Telnet, Hardcoded passwords, …
- **Physical tamper resistance**: Glitching, Side channels, Enclosures, …
- **RTOS and bare metal**: Stack overflows, MPU config, ISR safety, …
- **Industrial OT and SCADA**: Modbus exposure, PLC programming, Safety systems, …
- **Medical and safety devices**: FDA cyber, Patient harm, Update windows, …
- **Automotive and CAN**: CAN injection, OBD ports, OTA vehicles, …
- **IoT cloud backends**: Device provisioning, Certificate lifecycle, Fleet management, …
- **Botnet and abuse**: Mirai patterns, Telnet scanning, Credential stuffing C2, …
- **Firmware supply chain**: Third-party SDKs, Chip vendor blobs, CI for embedded, …
