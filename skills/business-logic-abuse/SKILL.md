# Business logic and abuse prevention

## When to use

Load this skill when work touches **business logic and abuse prevention**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Payment and checkout abuse**: Coupon stacking, Currency, …
- **Workflow bypass**: State machine skips, …
- **Insecure direct object references**: UUID guessing, IDOR in APIs, …
- **Mass assignment**: Hidden fields, DTO allowlists, …
- **Bots and automation**: CAPTCHA alternatives, Behavior, …
- **Referral and loyalty abuse**: Self-referral, …
- **Marketplace trust**: Chargeback, Escrow, …
- **Content abuse**: Spam, Illegal content, …
- **Quota and limit bypass**: Parallel requests, …
- **Admin misuse**: Separation of duties, …
- **Time-based logic**: Timezone, Leap seconds, …
- **Feature gating bypass**: Client flags, …
