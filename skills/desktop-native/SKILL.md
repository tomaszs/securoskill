# Desktop and native application security

## When to use

Load this skill when work touches **desktop and native application security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Electron hardening**: nodeIntegration, contextIsolation, Remote module, …
- **Tauri and hybrid native**: IPC surface, Capability permissions, Rust side APIs, …
- **Auto-update channels**: Code signing, Update signatures, Downgrade attacks, …
- **OS sandbox and permissions**: macOS sandbox, Windows capabilities, Linux portals, …
- **Local privilege escalation**: Installer perms, DLL hijacking, Setuid helpers, …
- **Clipboard and screen capture**: Sensitive copy, Overlay malware, Screen recording APIs, …
- **File handlers and URIs**: Custom scheme handlers, Path traversal open, Macro documents, …
- **IPC between components**: Named pipes, DBus, XPC, …
- **OS credential storage**: Keychain, Credential Manager, Secret Service, …
- **Debug symbols and dumps**: Crash reports PII, Core dumps, Symbol servers, …
- **Enterprise deployment**: MDM packages, Notarization, SmartScreen, …
- **Offline-first apps**: Local DB encryption, Sync conflict, Cached tokens, …
