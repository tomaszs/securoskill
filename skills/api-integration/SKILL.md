# API and integration security

## When to use

Load this skill when work touches **api and integration security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **REST API design security**: Versioning, Idempotency, Mass assignment, …
- **GraphQL security**: Depth limits, Introspection, Batching abuse, …
- **gRPC and protobuf**: mTLS, Message size, Auth metadata, …
- **Webhooks outbound and inbound**: Signature verification, Replay, SSRF from callbacks, …
- **OAuth2/OIDC for APIs**: Scopes, Client credentials, Token exchange, …
- **API keys and HMAC**: Rotation, Per-tenant keys, Constant-time compare, …
- **Pagination and filtering abuse**: Large offsets, Filter injection, Threat modeling and trust boundaries (Pagination and filtering abuse), …
- **CORS for APIs**: Credentials, Wildcard origins, Threat modeling and trust boundaries (CORS for APIs), …
- **OpenAPI and documentation leakage**: Hidden admin paths, Example secrets, Threat modeling and trust boundaries (OpenAPI and documentation leakage), …
- **Backend-for-frontend patterns**: Token handling, Aggregation leaks, Threat modeling and trust boundaries (Backend-for-frontend patterns), …
- **Legacy SOAP/XML APIs**: XXE, WS-Security misconfig, Threat modeling and trust boundaries (Legacy SOAP/XML APIs), …
- **Event buses and streaming**: Schema evolution, Poison messages, Threat modeling and trust boundaries (Event buses and streaming), …
