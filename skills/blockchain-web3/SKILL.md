# Blockchain, Web3, and smart contracts

## When to use

Load this skill when work touches **blockchain, web3, and smart contracts**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Smart contract vulnerabilities**: Reentrancy, Integer overflow, Unchecked calls, …
- **On-chain access control**:  Ownable, Roles, Timelocks, …
- **Oracles and external data**: Price manipulation, Stale data, Flash loans, …
- **Wallet and key security**: Seed phrases, Hardware wallets, Browser extensions, …
- **dApp frontends**: RPC endpoints, Chain ID, Wallet connect, …
- **Token standards**: ERC-20 quirks, ERC-721 callbacks, Permit signatures, …
- **DeFi composability**: Liquidity pools, Governance attacks, MEV, …
- **NFTs and metadata**: Off-chain metadata, IPFS pinning, Royalty bypass, …
- **L2 and bridges**: Withdrawal delays, Sequencer trust, Bridge exploits, …
- **Audit and formal methods**: Slither, Mythril, Invariant tests, …
- **On-chain privacy**: Address linking, Mixer legal risk, ZK proofs, …
- **Compliance and sanctions**: OFAC lists, Travel rule, Geoblocking, …
