# CMS, content platforms, and publishing

## When to use

Load this skill when work touches **cms, content platforms, and publishing**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Headless CMS APIs**: Preview tokens, Draft leakage, Webhook secrets, …
- **WYSIWYG editors**: Paste HTML, Embed iframes, Link protocols, …
- **Publish workflows**: Approver bypass, Scheduled publish, Rollback, …
- **Plugins and themes**: Third-party PHP, npm theme scripts, Update channels, …
- **Comments and UGC moderation**: Spam, Illegal content, Reporter abuse, …
- **SEO and metadata injection**: OpenGraph XSS, Canonical hijack, Sitemap poisoning, …
- **Media libraries**: SVG in CMS, PDF previews, CDN paths, …
- **Multi-site CMS**: Site IDOR, Shared users, Domain mapping, …
- **CMS search**: Elasticsearch public, Faceted leaks, Admin search, …
- **Marketing forms**: Webhook spam, PII storage, Captcha bypass, …
- **Static site generators**: Build-time secrets, ISR vs SSG, Decap CMS, …
- **CMS roles and SSO**: Editor vs admin, SSO mis-map, API users, …
