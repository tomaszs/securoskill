# AI and ML system security

## When to use

Load this skill when work touches **ai and ml system security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Prompt injection**: Indirect injection, Tool abuse, …
- **RAG and retrieval**: Poisoned documents, ACL on chunks, …
- **Model abuse and cost**: Token flooding, Unbounded context, …
- **Training data poisoning**: PII in datasets, …
- **Model and weight exfiltration**: API leakage, …
- **Agent tool invocation**: SSRF via tools, Shell tools, …
- **Unsafe outputs**: Code execution suggestions, XSS in chat UI, …
- **Red teaming LLMs**: Jailbreaks, Benchmarks, …
- **Fine-tuning access**: Tenant isolation, …
- **Embeddings privacy**: Membership inference, …
- **MCP and external tools**: OAuth to tools, Scope, …
- **AI governance**: Human review, Logging prompts, …
