# AI and ML system security

## When to use

Load this skill when work touches **ai and ml system security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Prompt injection**: Indirect injection, Tool abuse, Threat modeling and trust boundaries (Prompt injection), …
- **RAG and retrieval**: Poisoned documents, ACL on chunks, Threat modeling and trust boundaries (RAG and retrieval), …
- **Model abuse and cost**: Token flooding, Unbounded context, Threat modeling and trust boundaries (Model abuse and cost), …

- **Unsafe outputs**: Code execution suggestions, XSS in chat UI, Threat modeling and trust boundaries (Unsafe outputs), …
