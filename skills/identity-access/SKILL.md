# Identity, authentication, and access control

## When to use

Load this skill when work touches **identity, authentication, and access control**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Passwords and credentials**: Hashing, Pepper, Breached password checks, …
- **MFA and step-up auth**: TOTP, WebAuthn, Recovery codes, …
- **SSO and federation**: SAML, OIDC, JIT provisioning, …
- **RBAC**: Role explosion, Default roles, Threat modeling and trust boundaries (RBAC), …
- **ABAC and policy engines**: OPA,  Cedar, Policy tests, …
- **Service accounts and workloads**: SPIFFE, IAM roles, Threat modeling and trust boundaries (Service accounts and workloads), …
- **Break-glass and emergency access**: Audit, Time bounds, Threat modeling and trust boundaries (Break-glass and emergency access), …
- **Account lifecycle**: Joiner-mover-leaver, Orphan accounts, Threat modeling and trust boundaries (Account lifecycle), …
- **Privilege escalation**: Horizontal, Vertical, IDOR, …
- **Zero trust access**: Device posture, Continuous auth, Threat modeling and trust boundaries (Zero trust access), …
- **Biometrics and device binding**: Liveness, Replay, Threat modeling and trust boundaries (Biometrics and device binding), …
- **Guest and anonymous access**: Scoped tokens, Rate limits, Threat modeling and trust boundaries (Guest and anonymous access), …
