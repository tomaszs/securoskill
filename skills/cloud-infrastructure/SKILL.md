# Cloud and infrastructure security

## When to use

Load this skill when work touches **cloud and infrastructure security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Cloud IAM**: Overprivileged roles, IAM conditions, …
- **Object storage buckets**: Public ACLs, Policy mistakes, …
- **Compute instances**: IMDSv2, SSH keys, Metadata, …
- **Managed serverless**: Function URLs, Concurrency, …
- **Secrets managers**: Rotation, Access policies, …
- **VPC and security groups**: 0.0.0.0/0, Peering leaks, …
- **Cloud audit logs**: Tampering, Retention, …
- **Infrastructure as code**: State files, Drift, …
- **Multi-cloud identity**: Federation, Key sprawl, …
- **SaaS admin consoles**: MFA, SCIM, …
- **CDN and edge**: Cache deception, Origin shield, …
- **DR and regions**: Failover security, Data residency, …
