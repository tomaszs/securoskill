# Secrets and configuration

## When to use

Load this skill when work touches **secrets and configuration**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Environment variables**: Leaks in logs, Client exposure, …
- **Config separation**: Per-env files, Gitignore, …
- **Feature flags**: Kill switches, Privileged features, …
- **Secret rotation**: Dual-write, Breakage windows, …
- **.env handling**: Committed secrets, CI injection, …
- **Config servers**: ACLs, Encryption, …
- **Hardcoded credentials**: Scanning, Prevention, …
- **Public vs confidential clients**: Mobile apps, SPAs, …
- **Bootstrap secrets**: First deploy, Init containers, …
- **Configuration audit**: Drift detection, …
- **Insecure defaults**: Debug=true, Open admin, …
- **Split knowledge**: Shamir, M-of-N, …
