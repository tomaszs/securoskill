# Email and notifications security

## When to use

Load this skill when work touches **email and notifications security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Email authentication**: SPF, DKIM, DMARC, …
- **Template injection in email**: SSTI in mailers, …
- **Links in email**: Open redirect, Tracking, …
- **Bounce and webhook handling**: Forged events, …
- **List management**: Header injection, …
- **Brand impersonation**: From addresses, BIMI, …
- **Attachments**: Malware scanning, …
- **SMS and push**: OTP leakage, SIM swap awareness, …
- **User inbox rules attacks**: Forwarding rules, …
- **Email provider APIs**: API keys, Send-as, …
- **PII in email bodies**: Encryption, Retention, …
- **Email abuse**: Forgot password spam, …
