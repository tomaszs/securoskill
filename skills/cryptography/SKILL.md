# Cryptography and key management

## When to use

Load this skill when work touches **cryptography and key management**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **TLS and certificates**: mTLS, Pinning pitfalls, Cert rotation, …
- **Symmetric encryption**: AES-GCM, Nonce reuse, Key derivation, …
- **Asymmetric crypto**: RSA padding, ECDH, Signature algorithms, …
- **Hashing and passwords**: bcrypt/argon2, SHA-256 misuse, …
- **Randomness and IDs**: CSPRNG, Predictable UUIDs, …
- **KMS and HSM**: Envelope encryption, Cloud KMS policies, …
- **JWT and JOSE**: alg none, Key confusion, JWK sets, …
- **PGP and email crypto**: Key management, Ubiquitous encryption gaps, …
- **Specialized crypto uses**: Tokenization, Format-preserving, …
- **Crypto agility**: Algorithm deprecation, Inventory, …
- **Secrets derivation**: PBKDF2, scrypt, HKDF, …
- **Side channels**: Constant-time compare, Padding oracles, …
