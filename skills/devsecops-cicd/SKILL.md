# DevSecOps and CI/CD

## When to use

Load this skill when work touches **devsecops and ci/cd**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **CI secrets**: Fork PR leaks, OIDC to cloud, …
- **Static analysis**: False positives, Gate policy, …
- **Dynamic analysis**: Staging auth, Scope, …
- **Dependency scanning**: SBOM, License risk, …
- **Artifact signing**: Sigstore, Provenance, …
- **Branch protection**: Required reviews, Signed commits, …
- **Deployment gates**: Canary, Rollback, …
- **IaC scanning**: Terraform plan, Misconfig, …
- **Container scan in CI**: Blocking CVEs, …
- **Secret scanning**: Pre-commit, History rewrite, …
- **Environment promotion**: Prod data in lower envs, …
- **CI supply chain**: Third-party actions, Pinning, …
