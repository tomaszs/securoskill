# DevSecOps and CI/CD

## When to use

Load this skill when work touches **devsecops and ci/cd**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **CI secrets**: Fork PR leaks, OIDC to cloud, Threat modeling and trust boundaries (CI secrets), …
- **Static analysis**: False positives, Gate policy, Threat modeling and trust boundaries (Static analysis), …
- **Dynamic analysis**: Staging auth, Scope, Threat modeling and trust boundaries (Dynamic analysis), …
- **Dependency scanning**: SBOM, License risk, Threat modeling and trust boundaries (Dependency scanning), …

- **Container scan in CI**: Blocking CVEs, Threat modeling and trust boundaries (Container scan in CI), Abuse cases and adversarial testing (Container scan in CI), …

- **Environment promotion**: Prod data in lower envs, Threat modeling and trust boundaries (Environment promotion), Abuse cases and adversarial testing (Environment promotion), …
- **CI supply chain**: Third-party actions, Pinning, Threat modeling and trust boundaries (CI supply chain), …
