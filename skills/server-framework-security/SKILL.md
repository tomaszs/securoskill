# Server framework and runtime security

## When to use

Load this skill when work touches **server framework and runtime security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Node.js and Express**: Prototype pollution, Middleware order, JSON body limits, …
- **NestJS and Fastify**: Guards vs pipes, Validation decorators, GraphQL plugins, …
- **Django and Flask**: DEBUG=True, SECRET_KEY rotation, ORM extra(), …
- **FastAPI and Starlette**: Dependency injection auth, OpenAPI public, Background tasks, …
- **Spring Boot and Java**: Actuator endpoints, SpEL injection, Deserialization, …
- **ASP.NET Core**: Mass assignment, DataProtection keys, Kestrel limits, …
- **Ruby on Rails and Laravel**: Strong params, Mass assignment, Blade unescaped, …
- **Go net/http and Gin**: Handler auth middleware, Template html/template, Race in handlers, …
- **Rust web stacks**: unsafe blocks, SQLx literals, Tokio spawn abuse, …
- **PHP and WordPress class apps**: include paths, unserialize, upload dirs, …
- **GraphQL server frameworks**: Resolver authz, DataLoader leaks, Introspection prod, …
- **Serverless framework adapters**: Chalice, Serverless.yml secrets, SAM templates, …
