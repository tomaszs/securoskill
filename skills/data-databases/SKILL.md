# Data protection and databases

## When to use

Load this skill when work touches **data protection and databases**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Relational databases**: PostgreSQL, MySQL, Migrations, …
- **NoSQL stores**: MongoDB, DynamoDB, Redis, …
- **ORM and query builders**: N+1, Raw SQL escape hatches, Threat modeling and trust boundaries (ORM and query builders), …
- **Encryption at rest**: TDE, Column-level, KMS integration, …
- **Backup and restore**: Ransomware, Test restores, Offsite, …
- **Replication and CDC**: Lag, Read replica exposure, Threat modeling and trust boundaries (Replication and CDC), …
- **Data minimization**: Retention, Anonymization, Threat modeling and trust boundaries (Data minimization), …
- **PII and sensitive fields**: Tokenization, Masking in logs, Threat modeling and trust boundaries (PII and sensitive fields), …
- **Schema migrations safety**: Destructive changes, Locking, Threat modeling and trust boundaries (Schema migrations safety), …
- **Connection strings and pooling**: Credential rotation, TLS to DB, Threat modeling and trust boundaries (Connection strings and pooling), …
- **Row-level and column security**: RLS policies, Views, Threat modeling and trust boundaries (Row-level and column security), …
- **Search indexes**: Elasticsearch exposure, Leaked fields, Threat modeling and trust boundaries (Search indexes), …
