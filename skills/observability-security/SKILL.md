# Observability and debugging security

## When to use

Load this skill when work touches **observability and debugging security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **PII in traces**: Sampling, Scrubbing, …
- **Metrics cardinality abuse**: Label injection, …
- **APM and session replay**: Recording secrets, …
- **Production debugging**: Feature flags, Access, …
- **Error trackers**: Breadcrumbs with tokens, …
- **Log injection**: CRLF, Forged entries, …
- **Dashboard access**: SSO, Embedding, …
- **OpenTelemetry exporters**: Endpoints, Auth, …
- **Continuous profiling**: Heap dumps, …
- **Synthetic monitoring creds**: Stored passwords, …
- **RUM and client beacons**: Data minimization, …
- **Alert routing secrets**: Webhook URLs in alerts, …
