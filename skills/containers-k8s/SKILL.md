# Containers and Kubernetes

## When to use

Load this skill when work touches **containers and kubernetes**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Container image security**: Base images, SBOM, Signing, …
- **Kubernetes RBAC**: Cluster-admin, Namespace isolation, …
- **Network policies**: Default allow, Egress control, …
- **Kubernetes secrets**: etcd encryption, External secrets, …
- **Container runtime**: Privileged pods, Host mounts, …
- **Admission controllers**: OPA/Gatekeeper, Pod security, …
- **Helm charts**: Templated secrets, Chart provenance, …
- **Container registries**: Pull secrets, Retention, …
- **Sidecars and service mesh**: Token theft, Localhost trust, …
- **Windows containers**: Isolation levels, …
- **Docker Compose dev security**: Published ports, Volume mounts, …
- **Container escape vectors**: Kernel CVEs, Capabilities, …
