# Containers and Kubernetes

## When to use

Load this skill when work touches **containers and kubernetes**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Container image security**: Base images, SBOM, Signing, …
- **Kubernetes RBAC**: Cluster-admin, Namespace isolation, Threat modeling and trust boundaries (Kubernetes RBAC), …
- **Network policies**: Default allow, Egress control, Threat modeling and trust boundaries (Network policies), …
- **Kubernetes secrets**: etcd encryption, External secrets, Threat modeling and trust boundaries (Kubernetes secrets), …
- **Container runtime**: Privileged pods, Host mounts, Threat modeling and trust boundaries (Container runtime), …
- **Admission controllers**: OPA/Gatekeeper, Pod security, Threat modeling and trust boundaries (Admission controllers), …
- **Helm charts**: Templated secrets, Chart provenance, Threat modeling and trust boundaries (Helm charts), …
- **Container registries**: Pull secrets, Retention, Threat modeling and trust boundaries (Container registries), …
- **Sidecars and service mesh**: Token theft, Localhost trust, Threat modeling and trust boundaries (Sidecars and service mesh), …
- **Windows containers**: Isolation levels, Threat modeling and trust boundaries (Windows containers), Abuse cases and adversarial testing (Windows containers), …
- **Docker Compose dev security**: Published ports, Volume mounts, Threat modeling and trust boundaries (Docker Compose dev security), …
- **Container escape vectors**: Kernel CVEs, Capabilities, Threat modeling and trust boundaries (Container escape vectors), …
