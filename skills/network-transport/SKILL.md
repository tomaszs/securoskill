# Network and transport security

## When to use

Load this skill when work touches **network and transport security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **DNS security**: DNSSEC, Subdomain takeover, CAA, …
- **WAF and edge protection**: Rule tuning, Bypass, …
- **SSRF**: Metadata endpoints, URL parsers, Allowlists, …
- **Reverse proxies**: Header injection, Path normalization, …
- **VPN and private networking**: Split tunnel, Peering, …
- **DDoS and volumetric attacks**: Rate limits, Anycast, …
- **IP allowlisting pitfalls**: Spoofing, Shared NAT, …
- **HTTP request smuggling**: Front/back desync, …
- **WebSocket transport**: Origin checks, TLS, …
- **SMTP security**: STARTTLS, SPF/DKIM/DMARC, …
- **IPv6 and dual stack**: Unexpected exposure, …
- **Service mesh mTLS**: Identity, Policy, …
