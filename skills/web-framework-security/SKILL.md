# Web UI framework security

## When to use

Load this skill when work touches **web ui framework security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **React**: dangerouslySetInnerHTML, useEffect fetches, Server Components, …
- **Vue.js**: v-html, Template compilation, Vuex persisted state, …
- **Angular**: DomSanitizer bypass, bypassSecurityTrust*, HttpClient CSRF, …
- **Next.js and Nuxt**: API routes auth, Middleware bypass, ISR cache poisoning, …
- **Svelte and SvelteKit**: {@html}, Form actions, Hooks auth, …
- **Astro, Remix, and islands**: Hybrid rendering, Endpoint auth, View transitions, …
- **Client state libraries**: Redux persist tokens, URL state secrets, TanStack Query cache, …
- **Client routing security**: Route guards only client, Lazy route leaks, Deep link auth, …
- **i18n and locale**: RTL injection, Locale switch CSRF, Translation XSS, …
- **Design system components**: Slot content XSS, Icon SVG, Toast HTML, …
- **Storybook and dev tools**: Exposed Storybook, Mock auth in prod, Addon scripts, …
- **Micro-frontends**: Module federation trust, Shared dependencies, Cross-app postMessage, …
