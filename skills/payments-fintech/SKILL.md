# Payments and financial flows

## When to use

Load this skill when work touches **payments and financial flows**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Payment webhooks**: Signature verify, Idempotency, …
- **Card data handling**: Tokenization, SAQ-A, …
- **Refunds and disputes**: Authorization, …
- **Currency and rounding**: Manipulation, …
- **PCI scoping**: Networks, Segmentation, …
- **3-D Secure flows**: Friction, Bypass, …
- **Digital wallets**: Apple Pay, Google Pay, …
- **Payouts and KYC**: AML hooks, …
- **Internal ledger integrity**: Double entry, Audit, …
- **Tax and invoicing**: Tampering, …
- **Subscription logic**: Proration abuse, …
- **Fraud scoring**: Bias, Explainability, …
