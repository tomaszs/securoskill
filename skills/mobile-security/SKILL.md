# Mobile application security

## When to use

Load this skill when work touches **mobile application security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **On-device storage**: Keychain, Keystore, SQLite, …
- **Certificate pinning**: Bypass tools, Rotation, …
- **Reverse engineering resistance**: Obfuscation limits, …
- **Deep links and intents**: URL scheme hijack, …
- **Mobile OAuth**: PKCE, Custom URL schemes, …
- **Biometric APIs**: Fallback PIN, …
- **WebView bridges**: JS interfaces, …
- **Push notifications**: Payload sensitivity, …
- **App attestation**: DeviceCheck, Play Integrity, …
- **Sideloading and jailbreak**: Root detection limits, …
- **Screenshots and overlays**: FLAG_SECURE, Overlay attacks, …
- **Mobile SDK supply chain**: Third-party SDKs, …
