# Logging, monitoring, and incident response

## When to use

Load this skill when work touches **logging, monitoring, and incident response**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Structured logging**: Correlation IDs, PII redaction, …
- **SIEM and alerting**: Noise, Tuning, …
- **Audit trails**: Tamper evidence, Clock sync, …
- **Incident response playbooks**: Roles, Comms, …
- **Forensics readiness**: Memory dumps, Chain of custody, …
- **Vulnerability disclosure**: Safe harbor, SLAs, …
- **Security on-call**: Escalation, Paging hygiene, …
- **Security metrics**: MTTD, Patch latency, …
- **Deception and honeypots**: Legal, Scope, …
- **UEBA**: Insider threat, False positives, …
- **Post-incident review**: Blameless, Tracking, …
- **Lawful access logs**: Subpoena, Customer notice, …
