# Software supply chain

## When to use

Load this skill when work touches **software supply chain**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Package registries**: Typosquatting, Maintainer takeover, Threat modeling and trust boundaries (Package registries), …
- **Lockfiles and reproducibility**: Integrity hashes, Threat modeling and trust boundaries (Lockfiles and reproducibility), Abuse cases and adversarial testing (Lockfiles and reproducibility), …
- **Vendoring**: Fork drift, Patch review, Threat modeling and trust boundaries (Vendoring), …
- **Build integrity**: SLSA levels, Hermetic builds, Threat modeling and trust boundaries (Build integrity), …
- **Third-party SaaS**: DPAs, Subprocessors, Threat modeling and trust boundaries (Third-party SaaS), …
- **License compliance**: Copyleft in SaaS, Threat modeling and trust boundaries (License compliance), Abuse cases and adversarial testing (License compliance), …
- **Binary dependencies**: Provenance, Checksums, Threat modeling and trust boundaries (Binary dependencies), …
- **Git submodules**: Pinned refs, URL hijack, Threat modeling and trust boundaries (Git submodules), …
- **Internal packages**: Namespace, Publishing tokens, Threat modeling and trust boundaries (Internal packages), …
- **CVE response**: Triage, Emergency patches, Threat modeling and trust boundaries (CVE response), …
- **Malware in repos**: Obfuscated scripts, Postinstall, Threat modeling and trust boundaries (Malware in repos), …
- **SBOM distribution**: VEX, Consumer updates, Threat modeling and trust boundaries (SBOM distribution), …
