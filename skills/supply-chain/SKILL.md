# Software supply chain

## When to use

Load this skill when work touches **software supply chain**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Package registries**: Typosquatting, Maintainer takeover, …
- **Lockfiles and reproducibility**: Integrity hashes, …
- **Vendoring**: Fork drift, Patch review, …
- **Build integrity**: SLSA levels, Hermetic builds, …
- **Third-party SaaS**: DPAs, Subprocessors, …
- **License compliance**: Copyleft in SaaS, …
- **Binary dependencies**: Provenance, Checksums, …
- **Git submodules**: Pinned refs, URL hijack, …
- **Internal packages**: Namespace, Publishing tokens, …
- **CVE response**: Triage, Emergency patches, …
- **Malware in repos**: Obfuscated scripts, Postinstall, …
- **SBOM distribution**: VEX, Consumer updates, …
