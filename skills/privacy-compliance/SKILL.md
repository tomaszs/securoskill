# Privacy and compliance

## When to use

Load this skill when work touches **privacy and compliance**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Data subject rights**: Erasure, Export, Rectification, …
- **Consent management**: Granularity, Withdrawal, …
- **DPIA and risk assessments**: High-risk processing, …
- **Cross-border transfers**: SCCs, Adequacy, …
- **PCI DSS scope**: Card data, SAQ types, …
- **HIPAA-aligned controls**: PHI, BAAs, …
- **SOC 2 trust principles**: Evidence, Controls, …
- **Records of processing**: ROPA, Vendor maps, …
- **Children's data**: COPPA, Age gates, …
- **Marketing and tracking**: Cookies, Opt-out, …
- **AI and profiling**: Automated decisions, Transparency, …
- **Breach notification**: Timelines, Regulators, …
