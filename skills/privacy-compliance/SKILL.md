# Privacy and compliance

## When to use

Load this skill when work touches **privacy and compliance**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [reference.md](reference.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Data subject rights**: Erasure, Export, Rectification, …
- **Consent management**: Granularity, Withdrawal, Threat modeling and trust boundaries (Consent management), …
- **DPIA and risk assessments**: High-risk processing, Threat modeling and trust boundaries (DPIA and risk assessments), Abuse cases and adversarial testing (DPIA and risk assessments), …
- **Cross-border transfers**: SCCs, Adequacy, Threat modeling and trust boundaries (Cross-border transfers), …
- **PCI DSS scope**: Card data, SAQ types, Threat modeling and trust boundaries (PCI DSS scope), …
- **HIPAA-aligned controls**: PHI, BAAs, Threat modeling and trust boundaries (HIPAA-aligned controls), …
- **SOC 2 trust principles**: Evidence, Controls, Threat modeling and trust boundaries (SOC 2 trust principles), …
- **Records of processing**: ROPA, Vendor maps, Threat modeling and trust boundaries (Records of processing), …
- **Children's data**: COPPA, Age gates, Threat modeling and trust boundaries (Children's data), …
- **Marketing and tracking**: Cookies, Opt-out, Threat modeling and trust boundaries (Marketing and tracking), …
- **AI and profiling**: Automated decisions, Transparency, Threat modeling and trust boundaries (AI and profiling), …
- **Breach notification**: Timelines, Regulators, Threat modeling and trust boundaries (Breach notification), …
