# Zero trust and secure access

## When to use

Load this skill when work touches **zero trust and secure access**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Zero trust principles**: Never trust network, Explicit verify, Least privilege session, …
- **Device posture**: MDM, Disk encryption, Jailbreak detection, …
- **ZTNA and private access**: App connectors, Split tunnel, Exposed admin, …
- **Micro-segmentation**: East-west firewalls, Identity labels, Default deny, …
- **Service mesh identity**: SPIFFE IDs, mTLS STRICT, Authorization policies, …
- **Privileged access management**: Just-in-time, Session recording, Break glass, …
- **Conditional access policies**: Geo block, Risk score, Compliant device, …
- **Bastion-less admin**: SSO to cloud, IAM Identity Center, Short-lived creds, …
- **Workload identity federation**: OIDC to cloud, GitHub Actions, K8s service accounts, …
- **Network device trust**: 802.1X, NAC, Guest Wi-Fi isolation, …
- **Remote work access**: VPN alternatives, VDI, Clipboard exfil, …
- **Zero trust measurement**: Coverage metrics, Policy exceptions, Shadow IT, …
