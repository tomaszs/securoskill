# Data engineering, analytics, and BI security

## When to use

Load this skill when work touches **data engineering, analytics, and bi security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Warehouse access control**: Snowflake RBAC, BigQuery IAM, Row access policies, …
- **ETL credentials**: Airflow connections, dbt profiles, Spark keys in notebooks, …
- **Pipeline injection**: SQL in dbt, Dynamic partitions, User-supplied SQL, …
- **PII in analytics**: Hashing vs encryption, Join keys, Re-identification, …
- **BI and dashboards**: Embed tokens, RLS in Power BI, Export CSV, …
- **Data lakes**: S3 path traversal, Parquet metadata, Glue catalog ACL, …
- **Streaming analytics**: Flink state, Kafka Connect secrets, Exactly-once, …
- **Feature stores**: Point-in-time leaks, Training-serving skew, Offline online parity, …
- **Notebooks and ad hoc SQL**: Shared workspaces, Output history, Git sync secrets, …
- **Data contracts and quality**: Breaking schema, DQ alerts, Tampered sources, …
- **Third-party data feeds**: License scope, Resale restrictions, API keys shared, …
- **Analytics backups**: Snapshot sharing, Cross-account, Restore to dev PII, …
