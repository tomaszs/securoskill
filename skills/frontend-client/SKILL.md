# Frontend and client-side security

## When to use

Load this skill when work touches **frontend and client-side security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Cross-site scripting (reflected, stored, DOM)**: HTML injection in templates, dangerouslySetInnerHTML / v-html, URL fragment and postMessage handlers, …
- **CSRF and clickjacking**: Form posts, Cookie-based sessions, iframes, …
- **localStorage, sessionStorage, IndexedDB**: Token storage, PII in browser, Cache poisoning, …
- **Content Security Policy and security headers**: CSP, X-Frame-Options, Referrer-Policy, …
- **SSR and hydration security**: Serialized state, HTML injection at render, Islands architecture, …
- **Web Workers and WebAssembly**: Shared memory, postMessage trust, Wasm module integrity, …
- **Third-party scripts and tags**: Analytics, Chat widgets, Tag managers, …
- **Frontend auth flows**: OAuth redirects, PKCE, Implicit flow avoidance, …
- **Client-side file upload UX**: Type sniffing, Preview gadgets, Size limits, …
- **Accessibility vs security UX**: Captcha, Rate limit messaging, Screen reader safe errors, …
- **Mobile web and PWA**: Service workers, Web push, App shell caching, …
- **Frontend dependency risk**: npm supply chain, Transitive packages, CDN compromise, …
