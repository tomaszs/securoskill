# Real-time, WebSocket, and messaging

## When to use

Load this skill when work touches **real-time, websocket, and messaging**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **WebSocket authentication**: Cookie vs token, Reconnect, …
- **Room and channel authorization**: Join tokens, …
- **Message integrity**: Signing, Ordering, …
- **Presence leaks**: Online status, Typing, …
- **MQTT and IoT protocols**: ACLs, TLS, …
- **Kafka security**: ACLs, SASL, …
- **Redis pub/sub**: Unauthenticated instances, …
- **Server-sent events**: CSRF, Caching, …
- **Collaborative editing**: OT/CRDT authz, …
- **WebRTC**: ICE, TURN credentials, …
- **Fan-out abuse**: Large rooms, Bots, …
- **Message retention**: Legal hold, E2EE, …
