# Serverless, edge, and FaaS security

## When to use

Load this skill when work touches **serverless, edge, and faas security**: design, implementation, code review, or incident follow-up.

## Workflow

1. Skim sub-areas in [rules.md](rules.md) and pick those that match the change.
2. Apply rules from **policy → design → implementation → verification → operations** for each matching sub-area.
3. For SQL injection, XSS, SSRF, authz, secrets, or other classics, use the dedicated sub-section rather than generic advice.
4. Record gaps as security requirements or tests before merge.

## Sub-areas covered

- **Function authentication**: IAM roles, Function URLs, API Gateway authorizers, …
- **Event source trust**: S3 notifications, SQS/SNS, EventBridge, …
- **Secrets in serverless**: Env vars, Parameter Store, KMS grants, …
- **VPC and network placement**: NAT costs, Public subnets, Private API, …
- **Edge workers (CDN)**: KV stores, Request rewriting, Cache poisoning, …
- **Denial of wallet**: Unbounded invocations, Recursive triggers, Large payloads, …
- **Idempotency and retries**: Duplicate charges, Partial failures, DLQ handling, …
- **Local dev parity**: sam local, Serverless offline, Prod creds in dev, …
- **Multi-region functions**: Replication lag, Regional secrets, Failover auth, …
- **Wasm at edge**: Sandbox escapes, Memory limits, Module signing, …
- **Orchestration workflows**: State injection, IAM chaining, Long-running abuse, …
- **Platform limit abuse**: Timeout extension, Memory exhaustion, Tmp storage, …
